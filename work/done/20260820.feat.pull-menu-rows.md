# feat: pull-based menu rows (toggle + checkbox)

A menu item factory used to snapshot its display value (`index`, `checked`)
into the Flex tree at build time. Moving that value then meant rebuilding the
menu, and a rebuild fights Svelte's keyed children: rows keep stable ids, so
`invalidate` reuses the node and never re-runs `onMount`. Writing
`getElementById().textContent` to work around it stole Svelte's text node.

The answer is a second contract, not a change to the first: a row can **mount a
widget that reads live state**, on a node the widget owns.

```ts
type Pull<T> = {
  get: () => T;
  subscribe?: (onChange: () => void) => () => void;
};
```

`invalidate` keeps its job — menu **shape**: which rows exist, preview HTML,
filter results. It is not how a label or a tick moves.

## Two factories, two contracts

|              | Stateless `toggleMenuItem`      | Pull `pullToggleMenuItem`             |
| ------------ | ------------------------------- | ------------------------------------- |
| Display      | Snapshot `index` in the row      | Widget paints from `get()`             |
| After click  | Caller rebuilds the item         | Widget paints again; siblings on `subscribe` |
| Use when     | Menu already rebuilds            | Menu must not rebuild                  |

Not one function with `index | source`. The bug that started this was a hybrid
(snapshot plus DOM write). `checkboxMenuItem` had no working stateless story —
Settings never rebuilt, it just flipped `input.checked` — so it became
pull-only.

## Rules that came out of it

- `get` must read live state. A value copied at `menu()` time goes stale,
  because a rebuild reuses the mounted widget rather than remounting it.
- The write in `onToggle` / `action` must be visible to `get()` before the
  handler returns; the factory paints on the next line.
- `subscribe` is for a write that must move the row **after** the click has
  painted: a keyboard action, a second row on the same state, or an
  `invalidate` in your own handler.
- Use `FChild` `onMount`, not the Flex mount map — Flex runs `onMount` once, on
  the parent Flex instance.

## Changes

- **2026-08-19** — first cut: `lib/pull.ts`, `PullToggleLabel` / `PullCheckbox`,
  `pullToggleMenuItem`, `checkboxMenuItem` on `source`, BindingsEditor back to
  one `setMenu` with `focusBehaviour: 'first'`. Widget mounted on the **title**
  node via a new `stdMenuItem.titleOnMount`, which forced `canFilter: false`
  because the filter writes `derivedHTML` into title text nodes.
- **2026-08-19** — jsed's two element-indicator checkboxes need a notify:
  `invalidateMenu` alone cannot move a mounted box. `JsedCatalog.create` now
  owns a `notifier` and wraps `invalidateMenu` to fire it. It had to live in
  `create`, not in `misc()` — `getEntries()` re-runs on every menu build.
- **2026-08-19** — REVIEW.md found the Katex box never ticked. Cause: the
  factory closed over the `paint()` of *its own* `mount()` call, but only the
  first build ever mounts. Every later build's `paint()` was a no-op, and the
  clicked row is always the latest build. Fixed in the factory (option B), not
  just at the call site: `pull/registry.ts` maps host id → mounted widget, so
  `paint()` reaches the widget that is on the node. Release is identity-checked
  so an old teardown cannot evict a newer mount.
- **2026-08-19** — Katex additionally notifies after `invalidate` resolves, and
  all four of its rebuild paths went through one `refresh()`. Belt and braces:
  Svelte's `set_attributes` only touches keys present in the spread, and
  `checked` is not one, so a rebuild does not actually clear the tick — checked
  against svelte 5.49.2 rather than assumed.
- **2026-08-20** — layout change: label stays in the title, value moved to a
  right-hand fchild (`oneput__toggle-value`). `right` already took a builder,
  so `stdMenuItem.titleOnMount` was reverted out entirely, `canFilter: false`
  dropped (the row filters on its label again), and `PullToggleLabel` became
  `PullToggleValue`. Stateless `toggleMenuItem` was matched to the same layout
  so the two factories look alike.
- **2026-08-20** — the when-condition screen rendered empty. Not the value node:
  key capture leaves the captured keys in the input, and they filter every row
  out. The old `canFilter: false` had been masking it by pinning one row. Fixed
  by clearing the input in `whenFlagUI`, with the keys moved into the menu
  title. Row label `Menu open` → `Menu state`.
- **2026-08-20** — kbd badges: glyph modifiers read small, so the whole badge
  had been sized up, making letters too big. `bindingToKbdHtml` now tags glyphs
  with `oneput__kbd-symbol` and the two sizes are separate variables. Control on
  macOS renders `⌃`, matching `toDisplayString` in the capture display.
  BindingsEditor's own screens stopped printing raw `$mod+s` and now use the
  helper.
- **2026-08-20** — @2br `EdgeMetadata`'s `Arrow at target` / `Arrow at source`
  rows were hand-rolled `stdMenuItem`s interpolating state into the title;
  converted to stateless `toggleMenuItem` (its `run()` already rebuilds).
